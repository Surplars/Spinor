# 砺矢（Lishi VPU）M8：同指令整数元素重叠执行

M8 不新增指令，开始利用整数 lane 已有的连续发射能力。基础整数、非掩码结果运算可在前一元素尚未返回时继续取数与发射；比较产生掩码、FP、乘法、除法仍串行。整个 VPU 一次仍只执行一条向量指令。

## 调度与正确性

发射和退休解耦，发射时递增索引，退休依据返回的元素 tag 重建目的地址、字节使能与位偏移。完成必须等全部在途元素和 RAM 写入阶段排空。flush 取消在途所有权及 lane 有效位，候选 RAM 不提交。

源始终读已提交版本，写入候选版本；读取和写回可以同时进行，但不得访问相同物理 RAM 行。掩码读改写保留串行路径，避免并发修改同一掩码字节。

- 完整整数整机 RTL：四种配置各通过 1673 条命令、5126 次读取，覆盖全部 22 种合法 SEW/LMUL，原有整数乘除法与 CSR/掩码检查保留。
- FP/乘除法交错回归：1681 条命令、7422 次读取、102 个指令 flush、2 个上下文写后 flush，分级写回与排空断言启用。
- 专项并发回归：251 条命令、102 个 flush 场景，实测最高 2 个元素在途、15198 次读写重叠，无相同物理行碰撞；包含 vd=vs2、各 SEW、masked/prestart、响应背压及撤销后恢复。
- 专项映射后回归：73 条命令、13 个 flush 场景，验证映射网表的结果与原子提交；映射后不依赖优化前的内部观测信号，报告中的 max_inflight=0 不是硬件行为结论。
- 整机映射后代表性回归：200 条命令、410 次读取，结果和周期应与同一用例的 RTL 一致，见 receipt.json。
- 原有 FP、整数乘法与整数除法独立模块 RTL 与 M7 SHA 一致，其独立单元数值验证明确复用；当前整机接入重新验证。
- RAM 写入锥审计通过，未重新引入 FP 状态直接驱动 RAM 写端的长链。

## 性能与资源

220 组周期对照均校验最终结果，详见 [性能报告](performance.md) 和 [CSV](performance.csv)。LMUL8 满向量 vadd：INT8 vv 为 1687→798 周期/指令（2.11×），vx 为 1431→542（2.64×）；INT32 vv 为 439→222（1.98×）。VL=1 不获益，乘除法与 FP 代表性测试周期保持不变。

| Yosys xcup 自动映射 | M7 | M8 |
|---|---:|---:|
| 逻辑 LUT | 11044 | 11054 |
| FF | 8040 | 8093 |
| DSP48E2 | 9 | 9 |
| RAM64M8 / RAM32M16 | 32 / 5 | 32 / 6 |
| 最长数据单元跳数 | 16 | 16 |

增加 10 个逻辑 LUT、53 FF 和 1 个 RAM32M16。逻辑 LUT 数不包含 LUTRAM，不能把“增加 10 LUT”当作全部 LUT 资源增量；Yosys RAM32M16 额外消耗的存储 LUT 单独计。VRF 的映射保持 32 个 RAM64M8，新增的存储映射与保留整数 lane 返回 tag 有关。没有因此减少 RAM 使用或宣称真实时序改善。

300 MHz 下的 M元素/秒仅按模拟元素/周期换算。M8 尚未在 Vivado 实现，不继承 M5 的 WNS，没有新 SDF 或板级性能结论。当前仍受逐元素源取数限制，vv/vx 发射间隔为 6/4 周期，不等于每周期一个元素。

复现：`make verify-m8`，再运行 `make package-m8`。本轮不要求用户重新运行本地 Vivado。
