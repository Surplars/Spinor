# M6：整数向量乘法与云端时序筛选

M6 新增 `vmul / vmulh / vmulhu / vmulhsu` 的 `.vv`、`.vx` 形式，SEW 8/16/32/64，覆盖全部 22 种已支持的合法 SEW/LMUL 组合。保留掩码、vstart、源目标重叠、尾部不变、事务式提交、响应背压和 flush 规则。

## 执行结构

共享一个 16×16 无符号乘法器，部分积、移位对齐分别寄存，128 位累加分成四个 32 位加法周期；高半有符号结果以两个分级修正完成。此版本容量为 1，优先控制资源和长组合链，执行延迟较高；不代表每周期处理一个元素。没有加入 widening/MAC/div/rem。

## 云端验证

- 独立 Python 任意精度整数乘法 oracle：2734 组数值检查，110 个逐周期 flush 场景；RTL 和使用真实 DSP48E2 功能模型的 Yosys 映射后仿真均通过。
- 整机整数回归：1231 条命令、4044 次寄存器读取；包含每种乘法/操作数形式各 22 种配置、9 个乘法 flush 场景，以及已有整数和 CSR 用例。RamVector、RamVector16、RamVectorFlops 和 RamVectorFp 的 RTL 均通过。
- RamVectorFp 的整机映射后乘法回归通过，1231 条命令、4044 次读取、131496 个周期，与 RTL 的结果及周期完全一致。
- 原有 FP32/FP64 整机回归：1649 条命令、7358 次读取、102 个指令 flush、2 个上下文写后 flush 场景通过，写入分级断言启用；FP lane RTL 与 M5 完全一致。
- 另增 FP/整数乘法交错回归：1665 条命令、7390 次读取，8 种乘法形式与 FP 指令交替执行，检查现存 fflags/frm 保持与提交行为，通过。
- 映射后的 RAM 写入锥检查通过：FP 状态寄存器没有重新直接进入 RAM 写地址、数据或写使能的组合锥。

## 资源和结构参考

| Yosys xcup 自动映射 | M5 | M6 |
|---|---:|---:|
| 逻辑 LUT | 9743 | 10300 |
| FF | 7027 | 7593 |
| DSP48E2 | 8 | 9 |
| RAM64M8 / RAM32M16 | 32 / 5 | 32 / 5 |
| 整机最长数据组合单元跳数 | 16 | 16 |

乘法器单独映射为 661 LUT、574 FF、1 DSP；最长数据链 12 个单元跳数，包含 CARRY4 和 LUT，不能换算成 ns 或器件频率。整机增加 557 LUT、566 FF，跨模块优化导致增量与单模块资源不同。Yosys 的存储/DSP 推断与 Vivado 不完全一致，不应把上述数字与 Vivado 表格混合计算。

M6 未在 Vivado 中实现，300/500 MHz 通过状态均未知。M5 实际布线核对及云端参考误差见 ../cloud-m5/evaluation.md：M5 的 WNS +0.477 ns 不能继承为 M6 的时序结果。本次交付不要求立即再跑 Windows；先积累经云端功能和结构检查的改动，再集中验证。

源码和复现方式见 ../../docs/m6-integer-multiply.md；完整证据及输入 SHA 见 receipt.json。源代码包含历史 M5 runner，但 windows-m5 不可用于生成 M6 包。
