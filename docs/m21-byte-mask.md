# M21：字节并行掩码通路

目标仍为 ZU15EG-2、300 MHz。ISA 与 M20 相同，本轮优化8种mask逻辑及 vcpop/vfirst 的执行方式，并化简FP32输入规格化的前导零路径。公开类名 `SpinorVpu`；仍只容纳一条架构指令，没有增加指令级乱序或多发射。

## RAM 与执行

继续使用单读/单写、双版本128位RAM。只增加/复用三个8位暂存值：源字节、结果字节、有效位；不缓存整组向量源或复制RF。原有128位v0缓存供masked扫描使用。

掩码逻辑每次处理8个元素，绕过整数ALU的逐元素发射/返回。7个状态依次完成dispatch、源A读/取、源B读/取、候选目的读/写，下一字节继续。目的仍先复制到候选版本，因此未触及的字节、vstart前的位及VL后的位保留；边界字节按8位有效位读改写。所有源始终读已提交版本，即使vd=vs1/vs2/v0也不会覆盖未读取源。完成接受时翻转版本，flush不提交。

vcpop/vfirst每字节先取源并过滤VL和v0.t，再寄存有效字节，下一拍进行8位PopCount/优先编码。扫描与逻辑复用结果字节暂存器。计数最多128，累加只用scalar completion的低8位并零扩展，避免64位加法。vfirst命中立即完成，无命中返回-1。每字节4周期；短向量或首字节早命中可能比旧版多周期，详见完整周期对照。

初版把RAM字节选择、predicate、PopCount与累加放在同拍，公开顶层100ps连线假设预算升到3.641ns；扫描增加一级后重新综合与验证。该中间结果不作为发布网表。随后出现的FP32规格化路径使用平衡前导零树替换原来的编码器，保持所有raw32字段精确一致，不增加周期；全输入组合SAT重新核对固定HardFloat。

## 验证与周期

独立Python逐位真值/bit-list模型，检查全部32个向量寄存器、版本表、CSR、背压和flush。覆盖字节内所有边界、跨字节、VL外置位、128个one-hot索引、源目的别名，以及执行各阶段与等待完成时的取消。相同oracle也在冻结M20 RTL上运行，避免只比较两个不同测试程序。

VL=128、vstart=0时，8种mask逻辑从1929降到121周期，约15.94倍。扫描为时序多一级，最终结果以[M21报告](../reports/m21/evaluation.md)为准。旧220组整数/FP基准也重新核对结果及周期。RTL与映射网表功能仿真不等于器件时序仿真。

monitor ABI仍为1.0，ID更新为0x2101，caps=0x3ff。寄存器布局和命令接口保持原合同，见[CPU合同](cpu-spinor-contract.md)及[MMIO](monitor-soc.md)。

## 复现与时序边界

```bash
make bootstrap
python3 scripts/verify_m21.py
python3 scripts/package.py --milestone m21
```

本轮重新验证微架构、FP数值单元与集成；FP转换、整数乘除、LSU等RTL与M20逐字节一致，可按SHA复用当时的单元回归和局部证明。完整复现入口会重新生成这些证据。`receipt.json`区分复用单元与本轮整机检查。

Yosys/RapidWright只提供未布局条件预算，沿用家族弧、50/100/200ps每段连线与100ps建立假设。DSP相关端点、器件布线/时钟树/hold、RAM写与I/O时序未覆盖，-2速度档未校准。300MHz仍待真实器件验证。本轮没有完整RVV、Orbital接入或Linux计算驱动交付。
