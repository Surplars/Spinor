# 开发与注释规范

源码职责与阅读顺序见[源码导航](../src/README.md)。硬件实现按功能目录归类，公共类和生成器继续使用`package vpu`。新增源文件必须登记到[目录映射](../scripts/maintenance/source-layout.json)，生成器、验证顶层和实验模块分别放入对应目录。

## 注释要求

代码注释使用英文，项目指南使用中文。每个顶层`class`、`object`、`trait`用ScalaDoc说明职责；公开Bundle说明字段含义和所有权。硬件模块的说明应覆盖适用的时钟域、请求容量、握手、延迟、反压及flush/reset规则。纯组合辅助函数写明宽度、输入限制、返回编码和边界值。

长模块按语义块说明：配置与拥有者寄存器、译码、操作数获取、执行流水、写回、完成与取消。状态机分支说明进入条件、该拍完成的动作以及后续状态。多个`when`写同一寄存器时，说明优先级和不可破坏的提交条件。

以下内容必须在实现附近解释：RAM的读延迟和候选版本、部分写入与版本提交、已接受总线请求的排空、跨流水级的valid/标签对应、符号与宽度扩展、舍入与饱和、异常/停止后的恢复单位。注释应解释约束和原因；避免“给寄存器赋值”一类逐行翻译，也不要用无含义标题凑数量。

维护检查限制连续无注释的主体代码不超过40行，忽略空白和单独括号。这个门槛用于发现长块遗漏，评审仍需核对注释是否真实反映实现。历史版权声明必须完整保留；修改功能时同步删除或改写过时的“尚未实现”、固定延迟和功能范围描述。

## 修改与验证

```bash
make check
make compile
```

`make check`检查目录映射、声明ScalaDoc、长代码块、文档链接和维护检查器的负控制，不要求硬件永远等同M61。功能变更仍需运行针对实际修改的数值、握手、恢复或时序检查，并在报告中说明范围。

本次纯整理另外使用`make check-rtl`：先逐文件比较去掉注释和空白后的Scala token，保留字符串、常量和运算符，再将8个完整生成顶层与M61压缩参考SV逐字节比较。输出放在`/tmp/spinor-source-layout`，不覆盖已验收build产物。该命令是本轮重构的固定基线检查；后续有意修改硬件时应建立对应的新功能与时序证据。

公共端口或协议变化须同步[接入指南](integration.md)和相应协议文档。只调整目录或注释时，不重写历史receipt；原路径通过冻结快照解析。已有记录是当时的证据，当前源码入口以[文档导航](README.md)为准。
