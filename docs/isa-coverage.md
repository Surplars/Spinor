# Spinor 指令覆盖矩阵（M60）

当前语义验证见[M60重启分类](m60-classified-restart.md)，目录清账见[ISA清单](m57-isa-audit.md)。官方目录逐项核对完成，
未发现目录缺项；这不等于完整ISA语义验收或完整V/RVA23/Zvkt声明。

| 分组 | 当前实现 | 当前验证 |
|---|---|---|
| 整数/定点/掩码/排列/归约 | 213条基础V整数编码 | 官方名称/match/mask逐项一致；M57解码边界扫描，M60按规范重启分类 |
| FP32/64 | 101条基础V浮点编码 | 含宽窄转换、估算、FMA、归约、搬运；已有Spike/SoftFloat数值参考 |
| 配置/CSR | 3条vset、7个向量CSR；独立模式另有FCSR CSR | M57立即数vtype位域、寄存器高位、x0、六种CSR动作和只读/保留地址 |
| 访存 | 58条基础目录编码、NF展开310种形式 | 310种均有合法成功样本；M57补12种形式，M58字段故障/恢复 |
| Zvfhmin | 两种FP16/FP32转换定义 | M54实现；复用基础V已有编码，不重复增加目录计数 |
| Zvbb | 10类操作、16条编码 | M55实现，M57独立编码核对，M60加入全编码重启分类 |
| Zvkt | 规范范围分类、操作数延迟抽样 | M56每宿主预设43,560样本；全面验收未关闭 |

M58两预设新增235,088条参考命令：330种算术编码×22种配置×4种vta/vma数值矩阵，
以及每预设404个字段故障/FOF后真实算术/CSR场景。5项规范条款已有具体有界证据。
M59另有457,600条独立Python/SoftFloat参考命令，覆盖26种操作的重叠/非零vstart，
3项条款有界检查与23个明确合法/拒绝锚点；12,780个合法非零起点目标、5,847个有活动计算。
上述是单份语料计数，两预设均比较通过；不是所有算术编码/布局/起点的穷举。
固定Spike仅用于vstart=0的16,298场景模型交叉核对，非零算术起点不称为Spike差分。

M60两预设新增726,000条命令：330编码×22vtype×2布局×5profile的重启分类矩阵。
307种编码在非零起点有可见结果，23种按限制拒绝；每种编码也有起点0合法样本。
普通mask变换和carry/merge、whole、scalar例外分开，5720场景与M59模型再次校准。
不是直接非零Spike差分，也不是所有布局/数据的穷举。

375基础V+16Zvbb=391条目录项。计数不是覆盖百分比；访存NF展开后是另一种
643项计数口径。见[逐编码CSV](../reports/m57/isa-catalog.csv)与
[访存NF CSV](../reports/m57/memory-forms.csv)。

VLEN128/ELEN64、单lane、单指令在途；整数SEW8/16/32/64、FP32/64，以及
Zvfhmin要求的FP16转换。LMUL支持m1/m2/m4/m8及目标ELEN下合法分数配置。
完整Zvfh、BF16、向量crypto和更大VLEN/多lane不在当前范围；乱序不属于V完整性要求。
整数精简预设移除FP，不能据此声明完整基础V。

M57标准/Deep共175,556条Spike差分命令、2,024条独立保留策略命令。
原始解码部分VL0、LMUL1，不能冒充数值计算；完整RF/CSR仍逐条检查。
310种访存形式全部合法执行并比较RF、CSR、8KiB RAM。
维护版规范的混合EEW源保留形式与Spike分歧单独验证，不修改参考模型。

尚未关闭的是规范语义/测试映射、架构测试套件验收、访存异常与恢复条款、Zvkt
全面验证。[ACT4接入条件](act4-intake.md)已固定来源并清点，尚未生成或运行其ELF。
CPU取指/退休、VS/FS、MMU/PMP和一致性属于[宿主接入](cpu-spinor-contract.md)，
